What to fix – prioritised list

The site is in good shape: it is secure, loads fast on desktop, and scores 100 for SEO. The most important thing to fix is the slow response on mobile, caused mainly by one script (consultant.js) that keeps the phone busy for a long time. Beyond that there are a few small accessibility fixes and one optional security hardening step.

  1. Priority: high Effort: dev needed · Impact: Faster, smoother mobile experience and a better Core Web Vitals score

    Reduce the load that consultant.js puts on mobile phones

    On mobile the page freezes for about 411 ms while loading (Total Blocking Time), which is above the 300 ms comfort level. This can make taps feel slow and can lower the mobile performance score that Google looks at. The test data shows consultant.js as the heaviest script by far.

    How: Ask your developer to profile /static/js/consultant.895c86c0f2ae.js in Chrome DevTools (Performance tab, with CPU throttling on). Anything heavy, especially the 3 canvas animations on the page, should start only after the page has loaded or when the browser is idle (requestIdleCallback), or when it scrolls into view. The test runs in a headless browser with software rendering, which may overstate the cost of canvas animations. So check Search Console → Core Web Vitals to confirm the problem shows up for real visitors before investing heavily.

  2. Priority: medium Effort: 30 min · Impact: Easier reading for everyone and fewer accessibility complaints

    Fix low-contrast text on the Polish home page

    3 elements on the home page have text that is too hard to read against its background. This affects visitors with weaker eyesight or anyone reading in bright sunlight, and it lowers the accessibility score to 95.

    How: Ask your developer to run the axe DevTools extension or Chrome's Lighthouse on /pl/ and look under 'color-contrast' to find the 3 elements. Darken the text colour or lighten the background until the contrast ratio is at least 4.5:1 for normal text. The data does not say whether the problem is in the light or dark theme, so check both.

  3. Priority: medium Effort: 30 min · Impact: Better accessibility for screen-reader users, cleaner page structure

    Add a main landmark and group content into page regions

    All three pages checked (home, blog, contact) have no <main> element, and many pieces of content sit outside any landmark region. Screen-reader users rely on these to jump straight to the content.

    How: In the site template, wrap the unique page content in a single <main> element, and make sure the header sits in <header>, the menu in <nav> and the footer in <footer>. Because this is probably one shared template, one change should fix all pages.

  4. Priority: low Effort: 1-2 h · Impact: Extra protection against script injection and unwanted browser features

    Add a Content-Security-Policy and Permissions-Policy header

    These two optional security headers are missing. They are extra protection layers, not current holes, and the rest of your security headers are already in place.

    How: Ask your developer or hosting provider to add a Permissions-Policy header that switches off features you do not use (for example camera, microphone, geolocation). For Content-Security-Policy, start in report-only mode (Content-Security-Policy-Report-Only), check nothing breaks, and then enforce it. Allow your own domain and Cloudflare Insights, which is already loaded on the site.
