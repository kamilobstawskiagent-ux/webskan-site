What to fix – prioritised list

The site is in reasonable shape for search (SEO score 100, no mixed content, valid TLS 1.3 certificate), but it has gaps in security, sharing and content basics. The most important fix is to force all visitors onto the secure HTTPS version of one canonical address, because right now http:// and the non-www version are both served as separate copies of the site. Several quick wins follow, including security headers, a missing meta description and a slow mobile load.

  1. Priority: high Effort: 15 min · Impact: Security and no duplicate pages in Google

    Redirect HTTP to HTTPS

    Visitors who type or follow an http:// link get the site without encryption, and the audit found no redirect to the secure version. Google also sees duplicate copies of every page.

    How: In the nginx server config, add a port 80 server block with 'return 301 https://www.krakow.pl$request_uri;'. Or ask your hosting provider to switch on 'Force HTTPS'. Test by opening http://www.krakow.pl and checking that it jumps to https.

  2. Priority: high Effort: 15 min · Impact: Consolidates Google ranking and traffic stats

    Choose one address: www or non-www

    Both www.krakow.pl and krakow.pl load as separate sites with no redirect. This splits Google ranking signals and can confuse visitors and analytics.

    How: Pick www.krakow.pl as the main version, since it is already the one you use. Add a 301 redirect from krakow.pl to it in nginx or the DNS/hosting panel. Make sure the HTTPS certificate also covers krakow.pl.

  3. Priority: high Effort: 15 min · Impact: Avoids a site-wide browser warning

    Renew the TLS certificate in good time

    The certificate expires in 33 days. If it lapses, browsers show a full-page security warning and most visitors will leave.

    How: Check whether automatic renewal (for example Let's Encrypt with certbot) is set up. If renewal is manual, put a reminder in the calendar for about 2 weeks before the expiry date. Confirm the renewal after it runs.

  4. Priority: high Effort: 1-2 h · Impact: Security and trust

    Add security headers

    None of the standard protective headers are set. This leaves the site more exposed to clickjacking and script injection, and it lowers the Lighthouse best-practices score (77).

    How: In nginx, add these headers: Strict-Transport-Security (max-age=31536000), X-Content-Type-Options nosniff, X-Frame-Options SAMEORIGIN, Referrer-Policy strict-origin-when-cross-origin and a Permissions-Policy. Add Content-Security-Policy last, in report-only mode first, because it can break scripts if it is too strict. A developer can do this in under an hour.

  5. Priority: high Effort: dev needed · Impact: Faster mobile pages and better Google ranking

    Speed up the mobile load

    On mobile, the main content takes about 5.4 seconds to appear (LCP). Slow pages lose visitors and can hurt Google ranking. The server's first response is also slow, with about 0.5 s of possible savings.

    How: Have your developer enable server-side caching for the home page and look at what slows down the first response. Compress or resize the largest image above the fold and serve it in WebP. Remove unused CSS and JavaScript, which could save about 23 KB each.

  6. Priority: medium Effort: 15 min · Impact: More clicks from Google results

    Write a meta description and fix the page title

    The home page has no meta description, so Google picks random text for the search result. The title repeats 'Oficjalny serwis miejski' twice and is 69 characters long, so it may be cut off in results.

    How: Add a meta description of 140 to 160 characters that says what the site offers, in Polish. Shorten the title to something like 'Magiczny Kraków – Oficjalny serwis miejski'. In a CMS this is usually in the SEO or page settings of the home page.

  7. Priority: medium Effort: 30 min · Impact: Better-looking shared links and more clicks

    Add Open Graph tags for social sharing

    No Open Graph or Twitter Card tags were found. When someone shares the site on Facebook, LinkedIn or Messenger, the preview looks plain or random.

    How: Add og:title, og:description, og:image (about 1200x630 px) and og:url to the page head. Add twitter:card as well. Many CMSs and SEO plugins can do this from one settings screen.

  8. Priority: medium Effort: 30 min · Impact: Clearer page structure and a more professional look

    Add a heading structure and a favicon

    The home page has no H1 or H2 headings, which makes it harder for Google and screen-reader users to understand the page. No favicon was found, so browser tabs and bookmarks show a blank icon.

    How: Give the home page one clear H1 (for example the city name or the main message) and use H2 for the main sections. Add a favicon.ico and an apple-touch-icon in the page head.

  9. Priority: medium Effort: 30 min · Impact: Faster and more complete indexing

    Fix the sitemap

    The sitemap at /sitemap.xml returns a 404 error, so Google has no map of your pages. New or deep pages may be found more slowly.

    How: Generate an XML sitemap with your CMS or an SEO plugin and publish it at /sitemap.xml. Then add the line 'Sitemap: https://www.krakow.pl/sitemap.xml' to robots.txt. Submit it in Google Search Console.

  10. Priority: medium Effort: 1-2 h · Impact: Smoother page and better accessibility

    Fix the layout shift on desktop and the accessibility issue

    On desktop, the page shifts around while loading (CLS 0.24, where 0.1 or less is good). One dialog also has no accessible name, which is flagged as a serious problem for screen-reader users on every page tested.

    How: Set width and height on images and reserve space for banners or embeds that load late, which stops the shift. Add an aria-label or aria-labelledby to the dialog element (for example the cookie or popup window) so it has a name.

  11. Priority: low Effort: 30 min · Impact: Accessibility and image search

    Add alt text to images

    12 of 46 images have no alt text. This hurts visually impaired visitors and loses a little image-search traffic.

    How: Add short descriptions to those 12 images in the media library or the page templates. For purely decorative images, use an empty alt attribute (alt="").

  12. Priority: low Effort: 30 min · Impact: Fewer broken links and better privacy compliance

    Fix the Facebook link and third-party cookie warning

    The link to facebook.com/wwwKrakowPL returned an error, so visitors may land on a broken page. Lighthouse also flags third-party cookies, which can trigger browser warnings and privacy concerns.

    How: Open the link in a browser. If the page has moved, update it in the footer or header, and if it works it may only be blocking automated checks. Review which embedded services (videos, maps, social widgets) set third-party cookies and make sure the cookie notice covers them.
