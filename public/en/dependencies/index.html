Check your project dependencies

Upload the dependency file of a Python (Django, FastAPI, Flask) or Node.js application. A few seconds later you see which packages have known security vulnerabilities and which version to update to.

Supported files: requirements.txt (including pip freeze output), poetry.lock, uv.lock, pdm.lock, Pipfile.lock, package-lock.json, yarn.lock, pnpm-lock.yaml. No account, no charge.

What you get

  • A list of vulnerable packages, most serious first: name, the version in your project and the version that removes every known vulnerability.
  • Every vulnerability with its CVE number and a link to the source, with severity and the fixed version.
  • Packages that could not be checked – those without a pinned version – listed separately instead of silently skipped.

What happens to the file

The file is read in memory and is not stored. Only package names and versions are sent to the vulnerability database – the same information a public registry sees on every install. We do not need or look at your application code.

In a CI pipeline

The same check works from the command line and returns JSON:

curl -s -F file=@requirements.txt "https://webskan.com/api/deps/check?format=json"

The vulnerablePackages field is the number of packages with vulnerabilities; each one carries updateTo, the version to update to.

Why do it regularly

Dependencies that are clean today may have a vulnerability announced next month – the code has not changed, the knowledge about it has. A one-off check shows today's state. If you run many projects and want an e-mail when a new vulnerability affects one of them, write to kontakt@webskan.com – we are preparing continuous dependency monitoring.

Where the data comes from

From OSV.dev, which aggregates the GitHub Advisory Database (CC-BY 4.0), the PyPA Advisory Database (CC-BY 4.0) and the OpenSSF malicious packages list, among others. Webskan is not affiliated with these organisations. What is visible from outside your site is covered separately by the security score.
