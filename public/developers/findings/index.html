Finding ids

Everything audit_website, recheck_website and the PDF audit can report, by id. Use this page to decide what a CI job fails on, to tell an agent which findings are its job and which are the hosting provider's, and to look up what a fixed / new line in a re-check actually means.

How ids work

  • Shape. area.rule, optionally followed by @target: sec.header.hsts is site-wide, seo.h1.missing@/pricing/ is about one page, links.broken@https://…/file.zip about one link, a11y.color-contrast@/#dark about one axe rule on one page in one colour scheme. The part before @ is listed below; the target is whatever the finding is about.
  • Stable. The same problem produces the same id in every run, which is what makes the re-check diff (fixed / open / new / unverified) and the weekly Monitor comparison possible. Titles and details are human text and may change; ids do not.
  • Severity is one of high, medium, low, info. Some rules have a fixed severity, others pick it from a threshold (listed below). info is context, never a defect.
  • Areas: sec security · perf performance · seo technical SEO · a11y accessibility · ux usability · journey customer journeys in a real mobile browser · links broken links.
  • Unverified in a re-check means the target could not be checked this time (link blocked or timed out, page returned an error), so it is reported neither as fixed nor as new.
  • Performance ids (perf.*) move with network conditions. Gate on them with a threshold you accept, not on their mere presence; the Monitor's weekly diff excludes them for the same reason.

sec.tls.expiringhigh < 7 days, else medium (fires under 21 days)The certificate expires soon.Fix automatic renewal (certbot timer, host panel, CDN) – do not just renew by hand.

Performance – perf.*

Measured with Lighthouse on an emulated mid-range phone over simulated 4G, from the audit location. Values vary between runs; gate with a margin.

IdSeverityFires whenUsual fix
perf.lighthouse.incompleteinfoThe page did not finish loading within 45 s. No other perf.* finding is produced from that run, because its metrics would be inflated.Find the resource that never resolves from outside your network (third-party script, blocked geo); check the page in PageSpeed Insights.
perf.score.mobilehigh < 50, medium 50–89Lighthouse mobile performance score below 90.Work the specific perf.* findings below; the score follows.
perf.lcp.mobilehigh > 4 s, medium > 2.5 sLargest Contentful Paint above the Google threshold.Preload the hero image or font, serve it in a modern format and the right size, cut render-blocking CSS/JS, fix slow TTFB.
perf.cls.mobilehigh > 0.25, medium > 0.1Cumulative Layout Shift above threshold.Width/height on images and embeds, reserve space for banners and ads, font-display: optional or matching fallback fonts.
perf.tbt.mobilehigh > 600 ms, medium > 300 msTotal Blocking Time above threshold (the lab proxy for INP).Defer or remove heavy scripts, split long tasks, load tag managers and chat widgets after interaction.
perf.weight.mobilemediumTotal transferred bytes above 3 MB.Compress and resize images, drop unused scripts and fonts.
perf.heavy-script@file.jsinfoTBT is above 300 ms; names the single script with the most main-thread time.Profile that file; it is usually the first thing to defer or remove.
perf.blocking-scriptsmedium ≥ 3 scripts, else lowSynchronous scripts in <head> without defer/async.Add defer, or move the script to the end of <body>.
perf.opp.<lighthouse-audit>medium ≥ 1.5 s saving, else lowA Lighthouse opportunity estimates ≥ 0.5 s or ≥ 50 KB of savings (e.g. perf.opp.render-blocking-resources, perf.opp.uses-responsive-images).Follow the Lighthouse audit of that name.
perf.images.oversized@/pagelowImages have several times more pixels than their rendered size on a phone.srcset/sizes or an image CDN; export at the displayed size.
perf.images.no-dims@/pagelowThree or more images without width/height on a page whose CLS is above 0.1.Add the attributes or aspect-ratio in CSS.
perf.slow-response@/pagemedium > 5 s, low > 2.5 sTime to first byte of the HTML above threshold during the crawl.Page cache, object cache, fewer plugins, better hosting, a CDN in front.
perf.compression.nonemediumThe HTML response is not gzip/brotli compressed.Enable compression at the server or CDN.

Customer journeys – journey.*

The audit walks the site like a customer on a phone: opens the menu, searches for a word from the page, finds the contact form, adds a product to the cart and reaches checkout (nothing is submitted or paid), and requests a non-existent address. Each finding carries a screenshot.

IdSeverityFires whenUsual fix
journey.nav.failhighTapping the mobile menu button reveals no links.Usually a JavaScript error or a CSS breakpoint mismatch; see ux.js-errors.
journey.nav.not_foundmediumNo menu or menu button is visible on the first mobile screen.A visible hamburger button or inline links above the fold.
journey.search.failmediumSite search ends on an error page.Fix the search endpoint; test with a plain word.
journey.search.warnlowSearching for a word taken from the page's own heading returns nothing.Reindex, or check the search ignores accents and word forms.
journey.404.soft404mediumA random address returns 200.Return a real 404 status with the error page.
journey.404.blankhighThe error page is empty.A 404 page with menu, search and a link home.
journey.404.no_way_outmediumThe error page has no navigation.Same as above.
journey.404.server_errorhighA non-existent address returns 5xx.Fix the router or rewrite rule that crashes on unknown paths.
journey.shop.failhighProduct → cart → checkout does not reach the checkout page; the reason is in the title.Reproduce on a phone with a fresh session.
journey.shop.login_requiredhighCheckout demands an account.Enable guest checkout.
journey.shop.no_payment_methods_visiblemediumThe checkout page shows no payment methods.Show accepted methods before the customer types anything.
journey.shop.many_fieldsmediumCheckout has more than 14 fields.Hide optional fields, enable autofill, drop the account-creation block.
journey.shop.add_button_disabled_(out_of_stock_or_variant)lowThe tested product could not be added (out of stock or variant required).Check the customer gets a clear message; not a defect by itself.

Links – links.*

IdSeverityFires whenUsual fix
links.broken@<url>mediumA link found on the crawled pages (internal or external, up to 500 checked, up to 40 reported) returns 4xx/5xx or no response after a retry. The finding lists the pages it was found on. Links that answer 401/403/429/503 to automated clients are reported as blocked, not broken, and count as unverified in a re-check.Fix or remove the link; redirect if the target moved.

What to gate on

  • Always fail: any high. They are deterministic (redirects, exposed files, mixed content, robots, viewport, broken journeys) or far past a threshold.
  • Fail on new medium findings in a re-check, not on all medium findings – legacy debt should not block today's deploy, regressions should.
  • Do not gate on info, on perf.* without a margin, or on links.broken@ for external hosts you do not control (watch them in the Monitor instead).
  • The CI script and the CLAUDE.md block that implement this are in Make your coding agent verify every deploy.
